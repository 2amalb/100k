# EGOX · Локации 100k

Сайт показывает, сколько из 100 000 часов закрыто и сколько точек ещё найти. Здесь же ведутся локации и выезды, а история пишет, кто и что поменял.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | Весь сайт одним файлом |
| `manifest.webmanifest`, `sw.js`, `icons/` | Установка как приложение на телефон и компьютер, иконка EGOX |
| `supabase/schema.sql` | Таблицы, права доступа, история изменений, запрет удаления |
| `supabase/seed.sql` | 11 категорий, 93 типа площадок, 25 локаций, 4 выезда, команда |

## Как запустить

### 1. Supabase
1. На supabase.com создай проект: New project, регион Frankfurt.
2. Открой SQL Editor, вставь весь `supabase/schema.sql` и нажми Run.
3. Перед вторым файлом открой `supabase/seed.sql` и впиши почты команды в блок `team_members`. Войти смогут только эти почты.
4. В SQL Editor вставь `supabase/seed.sql` и нажми Run.
6. Открой Authentication → URL Configuration и укажи в Site URL адрес сайта, например `https://egox.github.io/egox-locations/`. Этот же адрес добавь в Redirect URLs.
7. Открой Project Settings → API и скопируй Project URL и anon public key.

### 2. Ключи
Вверху `index.html` есть блок НАСТРОЙКИ. Вставь туда два значения:
```js
const SUPABASE_URL      = 'https://xxxx.supabase.co';
const SUPABASE_ANON_KEY = 'eyJ...';
```
anon key публичный, его можно хранить в коде: доступ защищают правила в базе. **service_role key в код не вставлять никогда.**

Пока ключи пустые, сайт работает в демо-режиме, и данные сохраняются только в браузере.

### 3. GitHub Pages
1. Залей файлы в репозиторий.
2. Открой Settings → Pages и выбери Source: Deploy from a branch, `main`, папка `/root`.
3. Через 1–2 минуты сайт откроется по адресу `https://<аккаунт>.github.io/<репозиторий>/`.
4. Свой домен подключается там же, в поле Custom domain. У регистратора домена нужна CNAME-запись на `<аккаунт>.github.io`.

## Как устроено
- **Вход** по почте и паролю. Пользователей создаёт админ: Supabase → Authentication → Users → Add user (галочка Auto Confirm User). Пускает только почты из `team_members`.
- **Удалять нельзя ничего.** Если с точкой не получилось, ставится статус «Отказ» или «Не подходит». Отказ нельзя сохранить без причины.
- **История** пишется в `audit_log` автоматически триггерами базы. Записи нельзя ни исправить, ни удалить.
- **Итог выезда сам меняет статус локации**: «Договорились» → «Договорились», «Думает» и «Не застал» → «Переговоры», «Отказ» → «Отказ».
- **Часы точки** зависят от числа людей на предприятии: до 15 человек — 50 ч, от 15 до 99 — 100 ч, от 100 — 1 000 ч.
- **Изменения видны всем сразу**, перезагружать страницу не нужно (Supabase Realtime).
- **Языки:** UZ / RU / EN, переключатель в шапке. В базе всё хранится на русском, перевод только на экране.
- **Сводка:** сколько точек каждого размера уже есть и сколько ещё найти. То же по каждой категории: белым — есть, оранжевым — ещё найти.

## Добавить человека
Supabase → Table Editor → `team_members` → Insert row. Заполни поля: почта, имя, роль (`field` или `admin`).

## Ограничение писем
Встроенная почта Supabase отправляет всего несколько писем в час. Для команды из 5–10 человек этого обычно хватает. Если письма с кодом перестанут приходить, подключи свой SMTP: Authentication → SMTP Settings.

## Установить как приложение
- **iPhone (Safari):** Поделиться → «На экран Домой».
- **Android (Chrome):** кнопка «Установить» в шапке сайта, или меню ⋮ → «Установить приложение».
- **Компьютер (Chrome/Edge):** значок установки справа в адресной строке, или кнопка «Установить» в шапке.
